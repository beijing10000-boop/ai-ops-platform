# 有界目录用量分析

1. 直接使用 SSH MCP 解析已登记目标。查询文件系统容量或 inode 用 `ssh_diagnose_disk`，查询目录占用用 `ssh_diagnose_directory_usage`，两者分别呈现。
2. root 为用户要求且 SSH MCP 允许的绝对路径。原生工具每次只扫描下一层，受服务端路径白名单、8 秒超时和结果上限约束；不要传 command、depth 或未定义的参数。
3. 用户要求展开 N 层时，根目录为第 0 层，其直接子目录为第 1 层。默认展开 1 层；用户明确要求时可按预算展开至 5 层。每次读取返回的 top_directories，再对需要深入的实际返回子目录分别调用同一原生工具。不能只扫描一层就声称已查完五层。
4. 优先扫描占用较大的目录，整次目录任务最多展开 30 个子目录，并受平台更小的采集预算约束；需要更广范围时说明剩余目录，建议分次查询。服务端拒绝某路径时停止该分支，不用其他命令绕过。
5. 不把父目录和子目录重复相加，不把不同挂载点跨文件系统汇总成同一占比。显示路径、大小、已展开层数、采集时间和未扫描范围。结果含 incomplete/partial、超时、权限不足或子目录缺失时，必须原样解释为扫描不完整，不能写成“目录为空”。
6. 对占用高的目录只给供人工审阅的排查或清理建议；不执行清理、删除、轮转、重启或写入。
