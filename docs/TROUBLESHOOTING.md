# 排障

| 现象 | 检查 |
| --- | --- |
| 初始化凭据错误 | 运行 `docker compose exec -T web cat /app/data/bootstrap.token`，使用原部署值；不要重建主密钥 |
| 页面无法访问 | `docker compose ps`、8088监听、宿主机防火墙与访问IP；默认发布宿主机8088 |
| MCP 无法连接 | 连接管理验证当前表单；容器里的127.0.0.1不是宿主机；分别使用正确服务令牌 |
| SSH MCP 发现失败 | 服务至少v0.2.0，地址为 /mcp，包含 ssh_resolve_host；令牌未过期/撤销 |
| 主机关联失败 | SSH MCP 中填写相同数字Zabbix Host ID，唯一、启用、绑定凭据且核验公钥，令牌覆盖主机组 |
| SSH MCP 动作失败 | 独立服务查看任务、授权动作、日志权限、跳板与主机公钥；平台无本地SSH兜底 |
| 仅有监控分析 | 设备为 Windows/网络设备/VMware 等非Linux、SSH MCP 未启用或连不上、主机未登记/未授权或映射失败、预算不足都会限制实时补查；原因见报告“诊断范围 → 能力说明”，预算不足时见“证据覆盖”的跳过项（“预采集次数不足”）与“分析预算” |
| 飞书应用验证通过但没消息 | 确认发送开关、群ID、机器人在群内、消息权限、接收器已启用；令牌验证不证明全部权限 |
| 飞书登录失败 | 外部主机/协议与开放平台OAuth回调一致；管理员Open ID属于该应用并获授权 |
| 配置变更后验证状态消失 | 重新验证已保存连接，旧配置检测结果不能代表新地址/令牌 |
| 修改飞书应用后长连接未切换 | `docker compose --profile feishu restart feishu-receiver` |
| 任务一直排队 | 系统配置 → 服务与维护中查看队列长度与 Worker 注册数量，确认对应 worker 和 Redis 健康；注册记录不等同于业务执行成功 |
| 提交提示队列不可用 | 失败任务已记录，页面可查看原因；修复 Redis/worker 后在报告页重试，不要反复提交相同告警 |
| 报告显示执行进程中断（WorkerLost） | 执行时间超过“任务时间预算 + 2 分钟”（至少 10 分钟）仍未结束的任务会标记 WorkerLost，告警分析与问答 Worker（alert-analysis-worker、qa-worker）约每 10 分钟自动检查一次，不必等人打开任务；问答（飞书或 Web）超过最长的分析时间预算 + 2 分钟（至少 10 分钟）仍无结果的同样记为失败（WorkerLost）。查看对应 worker 日志，恢复服务后重试 |
| 飞书卡片显示“AI 分析中断” | 执行该分析的 Worker 中途退出（重新部署、内存不足等）。平台在超过最长的分析时间预算 + 2 分钟（至少 10 分钟）后改写卡片，不会重新执行；按卡片提示重新发起，并用 `docker compose logs alert-analysis-worker`（问答为 `qa-worker`）查看退出原因 |
| 任务失败，错误类型 QueueLost | 任务排队超过 10 分钟，而队列中对应的执行任务已不存在或已结束（Worker 在执行前退出、Redis 数据丢失或被清空），平台已将其结束，不会自动重跑。确认 Redis 与对应 Worker 正常（系统配置 → 服务与维护）后重新发起分析 |
| 任务已取消，错误类型 AlertRecovered 或 QueueExpired；告警中心显示“已取消” | 排队的自动分析开始前发现告警已恢复（AlertRecovered），或排队超过“复用同一触发器近期分析”的时长（默认 2 小时，该项设为 0 时按 2 小时）仍未开始（QueueExpired），因此没有执行，报告写明原因。QueueExpired 说明分析队列积压或分析 Worker 中断过：在 系统配置 → 服务与维护 查看“自动告警分析”的排队数与 Worker 数，用 `docker compose logs alert-analysis-worker` 查看原因。需要时在告警卡片上点“🤖 AI分析”手动分析（不做这项核对） |
| 告警卡片写“已有 AI 分析在排队”或“正在进行”，没有自己的分析 | 同一主机、同一触发器的前一条告警已有分析在排队或执行，本告警等它的结果：结果回复在那条告警的卡片下，卡片中的链接打开该次报告。需要单独分析本告警时点“🤖 AI分析”；不想复用时把“复用同一触发器近期分析”设为 0 |
| 飞书问答回复“AI 排队中” | 前面还有问题在分析（卡片写明还有几个），轮到后同一张卡片变为“AI 分析中”。写“问答分析服务暂未运行”时没有 qa-worker 在运行：在 系统配置 → 服务与维护 查看“飞书问答”的 Worker 数，用 `docker compose ps qa-worker` 与 `docker compose logs qa-worker` 检查 |
| 任务已取消，错误类型 DailyBudget；告警中心显示“超出每日额度” | 当天自动分析已达“自动分析每日 Token 上限”（系统配置 → 飞书配置）。计数含已结束分析的实际用量，以及排队中、执行中分析的任务 Token 预算；排队的分析开始执行前会再核对一次。需要时在告警卡片上点“🤖 AI分析”手动分析（不计入上限），或调高上限 |
| 更改模式后诊断仍只查监控 | 分析模式只决定预算，不决定是否使用 SSH；核对 Zabbix 主机类型、SSH MCP 关联与报告“能力说明” |
| 报告为部分完成 | 查看“诊断不足与待核验”和逐项证据；采集失败、超时或预算耗尽不表示主机正常，也不等同于根因已证实 |
| 配置无法解密 | 保留旧APP_ENCRYPTION_KEY或原master.key，与对应数据库成对恢复 |

查看日志：`docker compose logs --tail=100 web alert-worker alert-analysis-worker qa-worker diagnostic-worker`。日志/工具采集失败代表证据不足，不能推断主机正常或故障根因。
