# v0.8 运维流程与产品优化

面向通过 Zabbix 监控 Linux、Windows、网络设备和虚拟化环境的运维团队，核心工作流为：接收告警 → 定位事件 → 核验主机 → 双 MCP 获取证据 → 阅读结论与不足 → 飞书协作和历史追溯。本轮改动围绕日常操作中的具体障碍展开。

| 问题 | 已实现的改进 | 验证 |
| --- | --- | --- |
| 告警多时难定位、问题与恢复分散 | 服务端分页，关键词/级别/恢复状态筛选，关联最近分析，从告警带入事件上下文 | 分页与恢复关联测试、浏览器操作 |
| 系统配置页面过长、切换后容易丢输入 | 四个页签，区域独立保存；未保存标记、离开确认；成员操作保留其他草稿 | 浏览器跨页签、离开与成员更新检查 |
| “配置已填”容易被理解成“服务已可用” | 总览区分完整性与最近连接验证；修改表单后验证结果失效，验证中的修改也会提示重测 | 草稿验证、健康记录与未变更保存回归 |
| 默认分析模式未被 Web 诊断采用 | 从后台读取配置模式，告警发起的诊断使用告警提示词 | 默认模式与提示词选择测试 |
| Linux SSH 采集依赖模型自行判断 | 保留标准/深度模式的自动首轮采集，提示词要求结合现有结果并避免重复；保持 Host ID、类型、权限与预算约束 | 已核验主机组及自动采集回归 |
| 报告轮询打断阅读、状态难懂 | 轻量状态轮询、中文进度，变化时更新详情且保留证据展开和滚动位置；隐藏标签页暂停轮询 | 浏览器定时刷新及状态接口测试 |
| 结论像原始文本、难保存 | 安全格式化标题/列表/代码，显示诊断不足；复制和 Markdown 下载，历史支持任务/事件/Trace ID 检索 | 内容转义、导出、搜索回归 |
| 队列故障后不知道任务去了哪里 | 保存失败任务并返回可查看报告，恢复后可重试；服务页显示队列和注册 Worker | 队列失败/重试测试、服务卡片检查 |
| 无变化的保存也清除健康记录、设置读取重复 | 仅保存实际变化的设置，管理页一次读取配置；报告状态轮询不重复读取证据或记录访问审计 | 设置差异与状态轮询回归 |

界面统一了间距、状态颜色、空状态、按钮和中文字体回退。桌面布局覆盖 1280、1440、1920 像素宽度；报告同时检查深浅色主题。截图位于 [screenshots](screenshots)，完整验证边界见 [TEST-REPORT.md](TEST-REPORT.md)。

本平台继续只连接两个独立 MCP；SSH 主机、凭据、公钥、跳板与动作授权仍由独立 SSH MCP 管理。保留历史数据兼容所需的读取逻辑，不恢复本地主机管理或 SSH 执行器。业务配置继续使用 Web 表单，运行状态使用可读卡片；诊断原始证据仅在有权限时展开查看。
